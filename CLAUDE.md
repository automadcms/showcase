# Showcase

A static gallery site showcasing real websites built with the [Automad](https://automad.org) CMS. No JS framework, no bundler — the page is generated by a bash script from a JSON data file and an HTML template.

## How it's built

- **`sites.json`** — the source of truth. An array of `{ title, url, screenshot }` objects, one per showcased site. `screenshot` is just a filename (e.g. `marcdahmen.de.webp`), expected to already exist in `public/screenshots/`.
- **`template.html`** — the full page shell (head, header, intro paragraph, `<main class="gallery">`). Contains a single literal placeholder string `__SITES__` inside the `<main>` tag, which gets replaced with the rendered gallery markup.
- **`build.sh`** — reads `sites.json` with `jq`, loops over the entries (`jq -r '.[] | [.title, .url, .screenshot] | @tsv'`), and renders one gallery-item snippet per site (an `<a class="gallery-item">` wrapping a `.gallery-frame` image and a `.gallery-title` caption). All snippets are concatenated and substituted into `__SITES__` using bash's `${template//__SITES__/$gallery}` (chosen deliberately over `sed`/`awk` to avoid `&`-escaping issues with HTML content). Output is written to `public/index.html`.
- **`public/styles/styles.css`** — all styling, linked from `template.html`. Colors are defined as CSS custom properties on `:root`.

Run the build with:

```
npm run build   # bash build.sh — regenerates public/index.html from sites.json + template.html
npm run serve   # php -S 0.0.0.0:8000 -t public — serves the public/ dir locally
npm run optimize  # node optimize-images.js — converts temp/*.png screenshots to optimized .webp in public/screenshots/
```

## Screenshot pipeline

Raw screenshots are dropped into `temp/*.png` (gitignored, see `temp/README.md`), then `npm run optimize` uses `sharp` to convert/compress them to `.webp` (quality 70) into `public/screenshots/`. The filename (minus extension) is expected to match the `screenshot` field referenced in `sites.json`. There is no automatic connection between `sites.json` and the optimize script — filenames must be kept in sync manually.

## Design direction

Visual inspiration came from `references/` (screenshots of other portfolio/gallery sites), most closely `gridsgallery.com`: light-grey square tiles with a centered, contained image and a small left-aligned caption below.

Established direction so far:
- **Typography**: Inter, loaded as a variable font via the unpkg CDN (`@fontsource-variable/inter`), no self-hosting.
- **Title ("Showcase")**: bold/heavy (800 weight), large (`clamp(3rem, 7vw, 5.5rem)`), tight line-height (0.9) and letter-spacing (-0.035em), uppercase — a deliberate Swiss-grid / International Typographic Style choice (heavy grotesque, tight tracking, poster-like scale).
- **Header layout**: flex row, `space-between`, `align-items: flex-end` so the small "Automad" link baseline-aligns with the bottom of the large title.
- **Intro paragraph**: same dark text color as the title (not muted), 1.25rem, semi-bold (600), max-width 50ch for readability.
- **Gallery grid**: intentionally uses **no media queries**. Responsiveness comes from `grid-template-columns: repeat(auto-fit, minmax(700px, 1fr))`, which lets the grid fit as many 700px+ columns as the container allows and reflow fluidly (down to 1 column) as the viewport narrows — no explicit breakpoints. Column gap is kept tight (0.5rem) while row gap is much larger (6.5rem), giving a lot of vertical negative space between rows while items stay close horizontally.
- **Gallery tiles**: square (`aspect-ratio: 1/1`) frames with a very light, slightly cool-toned grey background (`--color-frame-bg: #f2f4f6`), image centered via flexbox, `object-fit: contain`, capped at 85% of the frame's width/height. Image has a hairline border, `border-radius: 8px`, and a soft drop shadow (`box-shadow: 0 2.5rem 4rem -1rem rgba(0,0,0,0.2)`). On hover, the image shifts up 2% (`transform: translateY(-2%)`).
- **Main container**: wide — `max-width: 1920px` on `.wrapper`, generous outer padding (`5rem 2rem 7rem`).

## Known gaps / things to watch

- This project's dev sandbox cannot bind a listening TCP socket, so `npm run serve` cannot be verified from inside an automated session — visual checks need a human (or a session without that restriction) to actually load `http://localhost:8000`.
- `sites.json` and `public/screenshots/` must be kept manually in sync — adding a site means both adding an entry to `sites.json` *and* ensuring the referenced `.webp` file exists.
- `public/index.html` is a generated file (output of `build.sh`) — edit `template.html` and `styles.css`, not `public/index.html` directly, or changes will be lost on the next build.
